## 1. 背景与目标

原规格实现的"服务器 BAG 导出"只显示并导出 `*.bag`。本次需求:

1. **文件列表通用化**:不再过滤,目录下所有常规文件(及符号链接)都展示并可导出,使该功能成为通用的服务器文件导出工具;
2. **多选打包**:导出 N(N≥2)个文件时,自动打包为**一个 ZIP 文件**写入导出目录;
3. **"导出并打开"不变**:仍只允许恰好勾选 1 个 `.bag`(单文件裸导出后打开,不经过 ZIP)。

## 4. 桥接协议变更(v2)

桥接侧 `packages/ssh-bridge/src/protocol.ts`(kind/校验/版本)、`SshBridge.ts`(list 过滤)、`SshSession.ts` + `ssh2Connector.ts`(条目类型位),客户端 `ServerExportBridgeClient.ts`(kind 联合类型/版本号)同步修改,**不保留 v1 兼容路径**(决策 Z17)。

### 4.1 `kind` 扩展

```ts
export const PROTOCOL_VERSION = 2;
export type ListEntryKind = "bag" | "active" | "file";
```

`kindForName()` 判定顺序不变(先 `.bag.active` → `"active"`,再 `.bag` → `"bag"`),**其余常规文件/symlink → `"file"`**,不再返回 `undefined` 过滤掉。大小写归一化规则不变。

### 4.2 `list` 组装(SshBridge)

- **下发**:常规文件、符号链接(symlink 不做 target stat,直接按名字归 kind——名为 `x.bag` 的软链即 `"bag"`);
- **不下发**:子目录、socket/fifo/块/字符设备(按 SFTP `attrs` 的类型位判定);
- `SshFileInfo` 相应扩展条目类型字段(常规/目录/symlink/其他),由 ssh2Connector 按 SFTP `attrs` 权限位填充;**服务器未下发类型位时按常规文件下发**(实际不可读/不可流式读取时,走下载阶段既有失败流程);
- dotfiles 正常下发,不做特殊处理;
- 已知边界:symlink 指向目录时按 `"file"` 下发,下载阶段 SFTP read 报错进入失败流程(§8 边界清单)。

### 4.3 `download` 校验放宽

`validateDownloadPath()` 修订为:path 必须以最近一次 `list` 目录为前缀(不变);文件名部分**只拒绝 `/`**——v2 起 `\` 不再视为分隔符(Linux 下 `\` 是合法文件名字符;v1 的拒绝使原规格 §13.14 的"本地写入失败"路径实际不可达,本次一并纠正,Windows 解压风险见 §8.10/§11);**且 `kindForName(name) !== "active"`**(即只拒绝 `.bag.active`,其余名字均可下载)。其余防越权约束不变。

### 4.4 不变项

`connect`/`ack`/`cancel`/`fileStart`/`fileEnd`/二进制帧/`sshClosed`/错误码表/终止消息恰好一次/取消竞态定序/ack 窗口流控——全部沿用原规格 §4.3,**逐文件下载消息流零改动**(决策 Z1 的核心收益)。

## 5. 浏览器端 ZIP 流式打包设计

### 5.1 依赖

- `packages/studio-base` 新增依赖 **fflate**(MIT,`^0.8.x`;`yarn.lock` 中既有 `0.6.10` 仅为 `@types/three` 的 types 传递依赖,不可复用)。只用 `Zip` + `ZipPassThrough`(Store,不压缩),tree-shaking 后约 3–4KB gzip。

### 5.2 模块划分

新文件 `packages/studio-base/src/components/DataSourceDialog/serverExportZip.ts`(纯逻辑,不依赖 React):

- `createZipWriter(writable: FileSystemWritableFileStream)`:封装 fflate `Zip`,回调产生的 chunk 经**串行 promise 链**按序写入 `writable`(fflate 回调同步产出,`write` 异步,必须串行化保序);同时**累计已写容器字节**,供 §5.6 写入时护栏判定;
- `beginEntry(name, mtimeMs)` / `pushEntryChunk(chunk)` / `endEntry()`:对应 `ZipPassThrough` 生命周期;条目 mtime 取 `list` 的 `mtimeMs` 并**钳制到 fflate 可编码的 DOS 时间范围([1980-01-01, 2099-12-31],越界取边界值**——fflate 对越界年份直接抛错);文件名原样(fflate 对**非 ASCII** 名自动置 UTF-8 标志位,ASCII 名不置位,解压等价兼容);
- `finalize()`:写中央目录并 `writable.close()`(落点前按 §5.6 校验不越限);
- `abort()`:失败/取消路径——调用后 `beginEntry`/`pushEntryChunk`/`endEntry` 立即变为 no-op(**取消竞态期间迟到的二进制帧直接丢弃**,不再向串行链追加 write);丢弃 Zip 实例(**不调 `end()`**),等待在途 write 落定后 `writable.abort()`,再尽力 `dirHandle.removeEntry(zipName)`(忽略 `NotFoundError`);
- `zipFileName(date: Date)`:命名生成(**纯函数**);`resolveZipNameConflict`:重名序号探测(注入 `exists(name)` 以便单测)。

### 5.3 数据流(zip 模式)

```
WS onmessage(二进制帧)
  → ZipPassThrough.push(chunk)
  → Zip 回调产出容器字节(本地头/数据描述符/数据)
  → 串行链 writable.write(容器字节)
  → write 完成后发送累计 ack(**仍按条目文件字节计**,与 v1 相同:`onData` 仅在对应容器字节落盘后才 resolve,背压时点不变,桥接窗口语义精确不变,`ServerExportBridgeClient` 的 ack 记账零改动)
```

- `fileStart` → `beginEntry`;`fileEnd` → `endEntry` 后派发下一个 `download`(顺序单工不变);
- 单条目进度按**条目文件字节**计(不含容器开销),总进度分母 = Σ 勾选 size;**`fileStart` 携带的真实 size 与 list 不符时立即修正该文件份额**(对原规格"fileEnd 才修正"规则的修订——symlink 的 list size 为链接自身大小,差距可能极大,等到 fileEnd 进度会冲过 100%);`fileEnd` 兜底修正与失败/跳过/取消移除规则沿用原规格;
- zip 容器开销(**每条目**:本地头 30+nameLen、数据描述符 16、中央目录 46+nameLen;**每包一次**:EOCD 22)**不计入进度**,最终 zip 体积略大于 Σsize,文档说明即可。

### 5.4 命名与重名

- 导出开始时生成 `export-YYYYMMDD-HHmmss.zip`(本地时区);
- 写入前 `dirHandle.getFileHandle(name)` 探测(不 create),已存在则依次尝试 ` (1)`、` (2)`… 直至无冲突;
- **同一导出会话的重试沿用同一 zip 名**(决策 Z14);残留探测到则走同一加序号逻辑。

### 5.5 冲突预检的分模式处理

| 模式 | 预检 |
|------|------|
| 单文件(含"导出并打开") | 沿用原规格 §10:逐文件探测,三选一[全部覆盖/跳过已存在/取消],"已跳过(重名)"组保留 |
| zip(≥2) | 不再逐文件探测(文件在 zip 内,无本地重名概念);仅 §5.4 的 zip 名自动序号 |

### 5.6 大于 4GB 的限制(不支持 ZIP64)

- **已源码核实(fflate 0.8.x)**:流式写路径(`wzh`/`wzf`/`Zip`)不产出任何 ZIP64 结构(无 0xFFFFFFFF 哨兵 / 0x0001 extra 字段 / ZIP64 EOCD;ZIP64 仅存在于解压读路径),所有 size 与中央目录 offset 按 32 位写入,**越界静默截断且不抛错**;条目 >4GB 与累计 offset >4GB(多个小文件合计同样中招)都会产出损坏包。因此 >4GB 打包明确**不支持**(决策 Z15),ZIP64 支持列入 §12 扩展路线。
- 双层防护,阈值 `MAX_ZIP_BYTES = 0xFC000000`(4 GiB − 64 MiB,余量覆盖中央目录与在途条目开销):
  - **前置限制(UX 层)**:勾选总量(Σ list size)≥ `MAX_ZIP_BYTES` 时禁用导出按钮并提示分批(文案走 i18n);
  - **写入时硬护栏(正确性层)**:list size 对 symlink/增长中的文件不可信,预检可能被绕过——zip writer 累计已写容器字节(本地头/数据/数据描述符),越限即按 §7 整包作废,错误提示分批导出;`finalize()` 落点中央目录前同样校验不越限。

## 7. ZIP 模式异常与状态语义

整包作废(决策 Z4/Z13)的统一清理路径:

1. 停止派发后续 `download`;在途下载发 `cancel`(按原规格 §4.3 定序处理迟到消息,`fileEnd` 先到也不改变作废结局);
2. `zipWriter.abort()`(§5.2):丢弃 Zip 实例 → 在途 write 落定 → `writable.abort()` → 尽力 `removeEntry(zipName)`;
3. 条目归属:**已完成项计入失败组**(原因:取消→"已取消";失败中止→"打包已中止");**触发项**计失败组(附原始错误码);**其后项**计未开始组;
4. [重试失败项] = 整包重跑(决策 Z14)。

触发整包作废的情形:

| 触发 | 说明 |
|------|------|
| 用户取消 | 决策 Z13 |
| 任一条目下载失败(服务器 IO/断链/文件被删等) | 决策 Z4;单文件模式的"跳过继续"**不适用**于 zip 模式 |
| 任一本地写入失败(磁盘满/句柄失效) | zip 模式产物只有一个,**立即作废**,不适用单文件模式的"连续 2 次才中止"规则 |
| 容器字节超过 `MAX_ZIP_BYTES`(§5.6 写入时护栏) | 同本地写入失败:立即作废,提示分批导出 |
| 桥接 WS 断开 / `sshClosed` | 作废;[重试失败项] 先静默重连桥接+SSH(密码在内存)再整包重跑,沿用原规格 |

单文件模式的异常语义(连续 2 次本地写失败中止、冲突三选一、逐文件删除部分文件等)**全部沿用原规格**。

## 8. 边界情况清单(在原规格 §13 基础上新增/修订)

1. 【修订】原 §13.4 空目录 → 空态文案"该目录下没有文件";过滤无结果 → "没有匹配的文件"。
2. 【修订】原 §13.5 全是不可勾选项(仅 `.bag.active`)→ 导出按钮禁用(N=0),不变。
3. 【新】勾选 1 个非 bag 文件 → 单文件裸导出;[导出并打开] 禁用(非 bag)。
4. 【新】勾选 1 bag + 任意其他文件 → zip 模式;[导出并打开] 禁用+tooltip。
5. 【新】zip 名重名 → 自动 ` (1)` 序号;重试沿用原名,残留则加序号(§5.4)。
6. 【新】zip 模式任一环节失败/取消 → 整包作废+清理(§7);`removeEntry` 失败则残留部分包,在汇总页以次要信息提示手动清理。
7. 【新】取消与 `fileEnd` 竞态:无论哪种序先到,整包均作废删包;该条目按 §7.3 归属(原规格的"先到计成功不删除"仅适用于单文件模式)。
8. 【新】symlink 指向目录/断链 → 下载 `IO_ERROR`,zip 模式触发整包作废,单文件模式进失败组。
9. 【新】dotfiles、含空格/中文名 → 正常列出与打包;zip 条目名原样(UTF-8 标志位)。
10. 【新】Windows 不友好名称(`\`、CON/PRN 等保留名、尾随点/空格):单文件模式沿用原规格(本地写入失败进失败组——桥接 v2 放行 `\` 后,此类文件真正到达本地写入,`getFileHandle` 抛 TypeError);zip 模式**可正常打包**(条目在 zip 内不受本地文件系统限制),但 Windows 解压可能失败/落错目录——已知限制(§11)。
11. 【新】勾选总量 ≥ `MAX_ZIP_BYTES` → 禁用导出+提示分批;下载中实际容器字节越限(list size 对 symlink/增长文件不可信,预检被绕过)→ 护栏触发整包作废(§5.6)。
12. 【新】目录含子目录/socket/设备文件 → 桥接不下发,UI 无感知(决策 Z5/Z6)。
13. 【新】过滤框有值时点全选 → 只勾选过滤结果;清除过滤后其余勾选项仍在(摘要条提示"含过滤外 M 项")。
14. 【新】0 字节文件 → zip 内空条目,正常。
15. 【新】同目录大量文件(数千)→ 全量渲染,不设上限(决策 Z20)。
16. 【修订】原 §13.14 文件名含 `\` → zip 模式见本条 10;单文件模式不变。
17. 【新】symlink 指向 fifo/设备文件 → 服务器端 open 可能阻塞([取消] 可恢复:桥接 terminate 后立即发 `canceled`);指向 `/dev/zero` 类无限流(`fileStart` size=0)→ 持续写入直至本地写失败/取消,zip 模式整包作废,单文件模式进失败组。
18. 【新】条目 mtime 超出 DOS 时间范围(如 epoch 0 的脏文件)→ 钳制到边界值正常打包,不报错(§5.2)。

## 11. 已知限制与风险

1. **Windows 解压不友好条目名**(决策 Z16):含 `\` 的条目在 Windows 解压可能落错目录,保留名/尾随点可能解压失败;团队以 Linux 为主,接受并记录。单文件模式不受影响(写入时即报错)。
2. **symlink 逃逸**:download 校验仍是"last-listed 目录内按名字"约束,symlink 可指向目录外;桥接持用户本人 SSH 凭据,无权限放大,沿用原规格 §12 的风险立场。
3. **重试重传**:整包作废+整包重跑意味着大合集失败时已完成部分要重传(决策 Z14 的已知代价)。
4. **zip 体积 > Σsize**:容器开销不进进度分母,最终文件略大;显示以文件字节为准。
5. **版本不匹配文案方向**(决策 Z17):旧客户端 + 新桥接时,旧客户端固化的提示为"请升级桥接程序",方向恰好相反(应升级 web 应用);无兼容代码前提下无法根治——v2 发布须公告 **web 与桥接同步升级**。
6. **symlink 大小与进度为估计值**:list 不 stat symlink 目标(§4.2),摘要条与初始进度分母按链接自身大小计,`fileStart` 后修正(§5.3);>4GB 预检同样可能失真,由写入时护栏兜底(§5.6)。
